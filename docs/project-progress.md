# Wiki 多跳检索 Agent 项目进展

精选轨迹 SFT v2.1 在同一批 100 道本地留出题上，把答案匹配从 53 道提高到 64 道，把答对且找齐标注证据的题数从 27 道提高到 46 道。固定首跳后，10 道缺直接依据的开发题中有 3 道发起不同查询，0 道补到新支持句。后续实验重点是二跳查询能否找回模型缺少的证据。 [课程实验报告](course-results.md) · [固定首跳诊断](../runs/reopd/selected-sft-v2.1/grounded-summary.json)

## 实验方法与成果

项目使用 Qwen3-4B 搜索学生、HotpotQA 和 SQLite BM25。800 道题按用途划分，模型搜索 20,000 个共享检索块，每题最多搜索 6 次，每次最多返回 3 块。评测保存搜索查询、可见证据和最终答案，支持同题回放。 [数据与检索设置](hotpot-search.md)

训练从训练侧轨迹中优先选取 40 道原学生零检索答错题和 12 道从原学生真实首跳结果成功续查的题。每完整轮包含 48 条首查、48 条补查和 24 条提交动作。v2 与 v2.1 使用相同的 249 条训练动作和重复次数。v2.1 将学习率从 `2e-5` 提高到 `8e-5`，并混排批内动作，累计 32 次参数更新，训练和重载约 181 秒。两项改动的单独贡献仍待消融。 [训练配方与复现命令](selected-sft.md)

Answer EM 衡量答案匹配。Answer-Grounded 要求正常提交且答案匹配，同时看到含答案的标注支持句，或看到全部标注支持句。是非题按全证据判定。Strict 要求正常提交、答案匹配，且模型在对应文档中看到了全部标注支持句。Answer-Grounded 衡量轨迹中的可见证据，模型如何使用证据需要结合具体案例核查。v2.1 通过开发集门槛后，进入历史冻结留出集的事后同题对照。 [留出集汇总](../runs/reopd/course-extra/selected-sft/summary.json)

## 长期简历项目路线

| 优先级 | 实验 | 验收指标 |
| --- | --- | --- |
| 1. 验证复现与迁移 | 锁定 v2.1 配方，增加训练种子。锁定模型后跑 2Wiki 和一批未参与诊断的新题。现有 2Wiki 的 Strict 26→37 来自旧 A。 | 各种子的均值与波动、外部集合上的 EM、Answer-Grounded、Strict 和逐题得失。 |
| 2. 分析训练收益来源 | 在相同数据、token 预算和种子下补跑低学习率加混排、高学习率加原顺序。另用相同预算对比对齐学生失败现场与普通成功轨迹。 | 四组训练设置的配对结果，以及对齐失败现场的独立增益。 |
| 3. 补齐有效二跳示范 | 从训练侧保存真实首跳、缺失实体或关系、候选查询和实际新增支持句。保留能补证的查询、看似合理却无收益的查询，以及证据已足时及时提交的样本。先用有效动作做 SFT。 | 固定首跳后的补证率、已足证据题的正确提交率、直接给标准证据时的阅读正确率。 |
| 4. 验证策略与推理开销 | 回放候选查询确认检索器能找回支持句，再评估同状态偏好训练或小规模 RL。展示台记录延迟、输入输出 token 和搜索次数。 | 准确率与推理成本的变化，支持句召回与策略选择的逐题诊断。 |

当前可用于简历的表述

> 基于 Qwen3-4B 和 2 万个检索块搭建可回放的多跳问答环境，按学生真实失败状态筛选搜索与作答轨迹并训练 LoRA。在 100 道本地留出题的同题对照中，答案 EM 从 53% 升至 64%，答对且找齐标注证据的比例从 27% 升至 46%，平均搜索次数从 1.03 增至 1.52。通过固定首跳和直接提供标准证据的对照，定位二跳查询与答案提取的剩余问题。
