# 多跳搜索 Agent：从 SFT、教师 RL 到定向 ReOPD

状态：执行草案，不是已完成实验。主问题：相同学生、教师和训练预算下，把监督集中在“第一次搜索后可能过早作答、且可被教师纠正”的状态，是否比普通回放或继续 SFT 更有效？只做英文 HotpotQA、一套索引、一种故障；不把多跳标签当作必须调用两次的理由。

## 1. 两条路线与最小交付

|路线|自己做什么|复用什么|完成的含义|
|---|---|---|---|
|最小验证（先做）|搭好协议、运行基线、构建恢复池；从同一 SFT 学生分别完成一小段继续 SFT 与 ReOPD，保存并重载权重，做固定前缀与端到端评测|本地 HotpotQA、公开 Search SFT 学生和 GRPO 教师|证明数据和训练闭环可运行；不代表提升显著，也不叫自己做过教师 RL|
|完整实验（过门槛才做）|本地任务上生成 SFT 示范、训练并诊断 SFT、构建 RL 题和奖励、训练教师 GRPO；从同一学生初始化比较四组蒸馏/微调|仍复用环境与公开底模|得到能区分数据、算法、成本的报告；即便 RL 或 OPD 不胜也可交付|

建议最先用已发布的 Qwen3-4B 搜索 SFT checkpoint 作学生，同系列 4B 搜索 SFT-RL checkpoint 作冻结教师。大小相同并非为了压缩参数，而是减少规模差异、研究行为迁移。全流程自训时 Base、SFT 教师、RL 教师、SFT 学生各自记录来源；从 SFT 分叉，不能误把学生也初始化成 RL 教师。

## 2. 数据来源、划分和隔离

|来源|用途|使用限制|
|---|---|---|
|[HotpotQA](https://huggingface.co/datasets/hotpotqa/hotpot_qa)，现有本地 distractor/train 子集|300 道 sft_seed 采示范；300 道 rl 采轨迹、组内奖励与恢复前缀；100 道 dev 调参；100 道 test 最后评一次|都是本项目划分，不是官方测试。记录现有 manifest、索引哈希；同题所有尝试/前缀不跨区|
|本地 20,000 个英文检索块与 private gold|所有题共用 BM25 索引；用答案别名和支持证据评分|不向模型暴露 gold、题目专属候选集、reward 或失败标签。检查跨区重复问题和核心支持标题；不声称完全实体隔离|
|[官方搜索权重与阶段说明](https://github.com/BaohaoLiao/ReOPD/blob/main/docs/search.md)、[冷启动示范](https://huggingface.co/datasets/baohao/search-cold-start)、[RL prompts](https://huggingface.co/datasets/baohao/search-train)|拿模型做最小验证；查看原始训练格式或走官方复现路线|公开权重可能见过来源相同的问题；能对齐则按题干去重并报告，无法排除则不声称未见过|
|[4B 教师前缀池](https://huggingface.co/datasets/baohao/Search_Qwen3-4B-Instruct-2507_SFT-RL_Prefix)、[构池说明](https://github.com/BaohaoLiao/ReOPD/blob/main/data/README.md)|参考消息字段、验证逻辑、按轮次保留策略|不是本地恢复池。官方历史来自另一索引，不能与本地轨迹混作同环境证据|

## 3. 基座搭建：先能重放，再上 GPU

1. 本地准备：按 [检索文档](hotpot-search.md) 核对模型环境、语料和索引清单。按 [训练环境](hotpot-training-environment.md) 启服务。以下是现有命令，在项目根目录运行：

   ~~~powershell
   .\Start-HotpotSearch.ps1 -Training
   Invoke-RestMethod http://127.0.0.1:8020/health
   Invoke-RestMethod http://127.0.0.1:8021/health
   ~~~

2. 用上述训练文档的 reset/step 示例先手动跑 1 题：搜索、读已返回文档、finish、保存终止指标、释放 episode。固定 BM25、top_k=3、最多 6 次工具操作。验证同题同动作得到同一文档和排序；后端错误不计模型错误。
3. 新增协议适配器（待实现）：在官方搜索消息与本地 local_search/read_document/finish 之间选择并固定一套**模型可见协议**。若保留官方 search + 最终短答协议，将 search 映射为 local_search，不凭空生成 citations；缺少显式引用时分别报告答案 EM 和已观察支持文档覆盖率，不能称为引用正确率。若采用本地三动作协议，则所有组相同，并用本地 SFT 先校准，不能把协议不兼容解释成推理差。
4. 最小验证优先保留官方协议。评分器单列“答案正确且所需支持文档全部出现在已返回结果”，抽样核验文本确实支持答案；不把看到文档当作已经利用了证据。拉取 10 题验证格式解析、超时、终止与保存。
5. GPU 训练用独立 Linux/CUDA 环境，锁定上游 commit、slime 子模块、驱动、镜像、tokenizer 和 chat template。[官方安装入口](https://github.com/BaohaoLiao/ReOPD#-installation)。公开搜索配置默认 8 GPU；若走官方 wiki 检索方案还需约 132 GB 解压空间。本地 BM25 小环境不需要这套索引，但需要自行适配 rollout 和评分；不能只换数据路径。远程 GPU 不能直接访问 Windows 的 localhost，优先在训练机部署同哈希数据与服务，不对公网暴露训练接口。
6. 资源未知时先做单 batch 探针：教师冻结、学生生成一个动作、取教师/学生对应 token 的 log-prob、算 loss、反传、存取 checkpoint。记录峰值显存、tokens/s 和失败原因再估算预算。教师与学生必须核对词表、特殊 token、模板和因果位移。只能返回文本的教师 API 可采 SFT 示范，不能替代这里所需的 token 级教师打分。

## 4. 实施工单与验收

下表是建议排期（人日，不含排队与模型下载）；数量为计划阈值，不是实测。每项验收后再进入下一项。

|工单 / 时间|输入 → 操作|落地产物与通过条件|
|---|---|---|
|P0 环境，D1|固定模型、检索与预算；完成上一节的 1 题手动、10 题自动交互|环境锁文件、10 条轨迹；确认工具来自实际执行、无 gold 泄漏、后端故障可识别|
|P1 基线，D2–3|从 rl 按固定种子抽 100 题；同配置跑 Base、SFT、RL 教师。dev 只作评测。每题记录首次搜索后是继续查还是作答|逐题比较表，不只报均值；人工审 30 条错误，区分过早答、查错实体、读错、语料缺失与协议错误|
|P2 筛恢复题，D4–5|截在学生错误动作之前；同一前缀让教师独立续跑 3 次，至少 2 次答案正确且证据支持才候选；复核证据，普通前缀按轮次匹配|目标至少 20 个不同训练题的可重放病例，报告总候选数与筛选通过率。若不够，先扩大到剩余 rl 题；仍不够则重新选失败类型，不用 dev/test 补数|
|P3 最小训练，D6–7|同一 SFT 学生、同一恢复池；分别做 A 继续 SFT、D 定向 ReOPD，先各 1 个 batch，再做 10–30 次更新|审一条 token mask，确认权重实际改变且教师未变；重载 checkpoint 完成 10 题端到端评测。仅为 smoke，不据此声称收益|
|P4 对照实验，D8–10|达到资源与病例门槛后做下节四组；普通样本与恢复样本初始可按 3:1 混合，比例只在 dev 选；记录训练和造数成本|固定 dev 选点规则、保存配置和逐题差值；至少做一次种子复核，单种子结果标探索性|
|P5 最终评测，D11|冻结模型、代码和阈值；由独立离线评测入口一次性读取保留 test，训练 API 继续禁止 test|固定前缀恢复率、端到端成绩、调用数与配对区间；案例集含改善和退化；分开列个人工作和上游权重|

## 5. 训练怎么做

**可选上游自训（插在 P1 与 P2 之间，另计工期）：**

1. SFT：在 sft_seed 上用强教师盲跑，只保留动作合法、答案通过、必要证据可核验的完整示范；按题去重，保留直接答与需要继续查两类。只对 assistant token 算损失，屏蔽 observation 和 padding。先用 8 条做过拟合检查，再训练一段，用 dev 比较格式正确率、答案 EM、平均调用数和 Base。训练器需适配 HotpotQA 消息和评测协议。
2. 是否做 RL：在 rl 题上从 SFT 每题采 4 条；优先保留同组既有成功又有失败且可可靠评分的题。全错先查召回或补示范；全对题留作回归。报告保留率及按题型分布，不能仅凭 SFT loss 决定上 RL。
3. GRPO：从 SFT 初始化教师，固定每题采样数、工具预算和检索版本。建议最小奖励为“规范化答案匹配且观察覆盖全部支持文档”得 1，否则 0；先在成功、猜对无证据、错误、超预算样本上手算核对。记录组内奖励方差、全零比例、KL、长度和调用数；大量同奖组先修数据/奖励，别通过继续加步数掩盖。与同预算继续 SFT 在 dev 比较，只有策略与奖励成立才冻结新教师；否则记录负结果，最小路线继续用公开教师。

**必做下游训练：**

|组别|训练信号与数据|要区分的因素|
|---|---|---|
|A 定向继续 SFT|与 D 相同前缀配比，模仿教师在这些前缀上的成功动作|只要选对数据，是否不需要 OPD？|
|B 原策略回放|本地教师轨迹拆前缀；以 0.6^t 保留第 t 轮，学生在该前缀生成，教师评分|本地环境中的原方法基线，不是论文官方分数|
|C 非定向混合 ReOPD|普通教师前缀 + 未按恢复难度优先的学生前缀；匹配 D 的来源比例、步数和长度分布|是否只因为加入了学生走过的状态？|
|D 定向恢复 ReOPD|普通教师前缀 + P2 通过验证的学生失败前缀|定向筛选是否优于 C？|

每个 ReOPD batch：回放固定历史 → 当前学生采样下一动作 → 冻结教师在同一历史和学生已生成 token 上打分 → 用上游蒸馏实现更新学生，只在该动作上计损失。不可将教师续写当成学生采样，不沿用旧学生生成代替当前采样。学生训练时是否真的触发检索以服务计数为准。预算对齐以学生更新 token 为主，另报教师推理 token、探索调用和 GPU 小时。在线 OPD（完整学生 rollout）是扩展组，不是完成 MVP 的前提。

## 6. 数据契约、指标与继续/停止规则

- 建议新增运行目录 runs/reopd/<run_id>/；原始数据只读。保存 manifest.json、episodes.jsonl、prefixes.parquet、audit.csv、metrics.json、paired_results.csv 和报告。manifest 至少记录模型 revision、索引/划分哈希、采样种子、训练参数与父 checkpoint。
- 轨迹字段：qid、split、attempt、可见消息、原始动作、工具返回、文档 ID、终止原因、调用数；答案标签、奖励、证据与审核结果放单独评分侧。前缀另存 source、turn、failure_type、教师成功/尝试数、验证文档 ID、原轨迹 ID。快照必须足以用相同预算和可读文档集合恢复环境；不能只把对话文字拼回去。若无环境快照，reset 同题并依次重放原动作，逐步校验 observation hash。
- 主指标：相同的留出故障前缀集合，分母固定，恢复成功数 / 前缀数；同时给出涉及的不同题数。另报整套留出题端到端 EM、证据覆盖、简单题退化、平均工具调用、实际训练成本。端到端测试不能只抽教师能救回的题；报告该故障在自然流量样本中的占比。
- 每题多条前缀做配对 bootstrap 时按题聚类；少量病例报告分子/分母而非只给百分数。若 D 比 B 好但不优于 A，结论是优先采用定向 SFT；若固定前缀改善而端到端无收益，则先查故障覆盖率；若 100 道留出题区间太宽，结论是证据不足，不返工调 test。
- 首次资源审批点：P2 前不启动长训练。先交 20 个经核验的病例、普通对照样本、教师可恢复率和单 batch 成本，再决定做四组、缩小模型还是结束项目。没有可信故障或可靠教师，停止比硬跑出一个模型更有价值。
