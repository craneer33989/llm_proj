# 本地百科检索 Agent：后训练项目草案

**核心问题：在同一语料、工具和预算下，训练后的小模型能否更准确地判断下一步该查什么、什么时候可以停？** 第一版做英文百科事实问答、实体桥接和双对象比较，输出简短答案及逐项证据。不把开放式长报告、中英跨语检索或全量 Wikipedia 作为首版承诺。

## 复用什么，新增什么

现有 `hotpot_search` 已有 20,000 个共享检索块、SQLite BM25、Qdrant 向量及混合检索、带预算的 reset/step/finish 环境、隔离的 gold 和可回放日志。数据是 HotpotQA 英文百科段落，不是完整页面；300/300/100/100 分别为 SFT 种子、策略训练、开发和项目内留出测试。

仓库记录的一次原问题检索支持文档 Recall@10 为 BM25 87.5%、混合 84%、纯向量 75%。因此首版固定 BM25，保留向量作对照。训练端默认每次只返回 top-3，要按实际可见预算重测。教师盲采摘要 `data/hotpotqa/v1/multihop/teacher-pro-v1/summary.json` 显示：已尝试 3 题，严格多跳示范接收 0 条。先回放这三条，区分答错、证据未见、引用错误与多跳筛选失败；不能据此估计总体成功率。

## Agent 运行契约（拟增）

`问题 → 小模型决策 → 搜索或阅读 → 更新已见证据 → 同一模型再决策 → 带引用作答或报告不足`

- **策略：** 从通用 Qwen3-1.7B 起步。输入问题、历史查询、实际返回的原文和剩余预算；模型选择 `local_search(query)`、`read_document(document_id)` 或 `finish`，负责查询改写、停止和汇总。先不训练 embedding，不用强模型在线补救。
- **工具：** 复用现有服务；搜索和阅读都占预算，模型只能读已返回的文档。固定语料、索引版本、结果条数、上下文和最大调用数；gold、奖励、支持标题不进模型提示。
- **编排：** LangGraph 的 StateGraph 管理共享状态、动作校验、条件分支和轨迹日志；条件边只执行模型选的动作。训练与推理共用消息和动作格式，不写“桥接题必查两次”的路由规则。
- **终局：** 内部保留短答案和块引用以复用评分；面向用户扩为 `status, answer, claims[{text,evidence_ids}], missing, trace_id`。新增证据不足状态与对应评分；主动拒答与预算截断分别记录。程序可校验引用确实出现过，语义是否支撑主张须另外核验。

例：“小说 X 的作者出生在哪座城市？”如果第一段只确认作者 Y，则下一次查 Y 的出生地；若首批结果同时给出作者关系和出生地，则一次就停并引用两项事实；若始终没有第二项，则说明缺的是出生地证据。**多跳推理不等于多次搜索。** 比较题同理：两侧的属性和比较口径都要有依据。

LangGraph 的图是流程图，不是百科知识图。仅当日志证明“已识别桥实体但无法定位下一页”是主要瓶颈时，再从同版本页面链接构建 SQLite 邻接表，加 `follow_link` 做等预算对照。不得用金标准支持页直接连边。长篇综合报告同样后置：它需要按主张评估覆盖和引用，不能用短答案 F1 验收。

## 训练为何分三段

| 阶段 | 训练信号与执行 | 必须验证的边际收益 |
|---|---|---|
| SFT：学会正确行动 | 教师在真实工具上执行，回放验证轨迹；学习各步动作及有依据的短答案，屏蔽问题和工具输出的 loss。采一次即停、继续补桥、双侧比较、证据不足四类示范 | 对比原始模型，动作有效率提高；证据齐能停，只有桥实体能查对下一步 |
| OPD：从自己犯的错中恢复 | 用当前学生生成轨迹，教师在相同可见历史上给学生实际生成的 token 打 logprob，用兼容分词器估计反向 KL 更新，定期刷新学生轨迹 | 对比等量继续 SFT，在首跳搜偏、重复查询、比较缺一侧的固定诊断中，恢复率提高，正常题不退化 |
| RL：在证据和成本间取舍 | 同题采多条完整轨迹，先验证奖励排序，再尝试 GRPO；以完整任务结果作反馈，仅更新模型生成 token，约束相对参考策略的偏离 | 同预算下有证答对率提升，或同等质量下调用更少；与 SFT+RL 对照，区分蒸馏与 RL 的贡献 |

OPD 的硬前提是教师能给**指定学生序列**打分，不是返回自己生成文本的置信度。先做单题对齐实验，实测吞吐和峰值显存；教师可独立部署，不必本机常驻师生。若只有聊天文本，做学生状态上的教师纠错 SFT，单列实验，不声称做了 token 级 OPD。

现有终止奖励以答案为主，即使证据为零，答对仍保留大部分答案分。RL 前先做奖励单测：有证答对 > 无证猜对；材料确实不足时拒答 > 编造；材料充分时正确回答 > 一律拒答。可回答题联合计答案质量与证据覆盖，不可回答题独立核验；调用成本仅作次要项。检查全引、全拒、闭卷猜答三类投机策略。同题采样若全错或无奖励差异，先修数据或种子策略，不盲跑 RL。

## 交付顺序与验收

1. **诊断集和基线先行。** 给开发题标出最早证据充分的步骤；补单事实题、首批已充分的复合题和必须补桥的题。构造保留/移除关键证据的配对版本，排查重复段及替代证据后才标不可答。派生题继承父题划分，测试集不参与筛选。策略训练池预先安排 OPD/RL 分配并记录复用。
2. **交付可回放的最小 Agent。** 演示一次即停、二跳补证、证据不足三条轨迹。比较不检索、一次检索、原始模型自主检索、直接给 gold 证据的阅读上限。额外对齐一次/多次检索的总返回量，排除“多看文本所以变好”。把失败分为没召回、召回未见、看到不会用、答对没引证。
3. **小批采集，验证后才扩容。** 先试 30–50 道混合场景，报告示范接收率、拒绝原因和每条有效样本成本。严格多跳筛选只管桥接桶，不把一次正确停搜当作坏示范。300 题用于验证方向，不承诺泛化；扩充时沿用现有数据隔离规则。
4. **逐段训练、允许止步。** 同预算比较 Base、SFT、SFT+OPD、SFT+RL、SFT+OPD+RL，另用继续 SFT 控制额外训练量。记录教师/学生 token、GPU 时、延迟与调用数。在开发集选方案，冻结后再评最终测试集。
5. **主指标是有证答对率**（答案正确且所需证据已见并被引用）；同时报答案 EM/F1、证据 P/R/F1、不充分时提前结束率、充分后继续搜索率、可回答题误拒率、不可回答题误答率和平均调用数。按单跳、桥接、比较和不可答分别给出分子/分母及配对区间。100 道项目留出题上的小幅波动不视作确定增益。
