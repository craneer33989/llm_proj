# 早答复核路由：可演示的效果改进

## 运行方式

在项目根目录启动展示页面：

```powershell
.\.venv\Scripts\python.exe -m streamlit run hotpot_search/demo_ui.py --server.address 127.0.0.1 --server.port 8502
```

打开 http://127.0.0.1:8502，在“输入问题”中选择“早答复核路由”。页面显示最终答案、采用哪一路模型和逐步搜索轨迹。第一次运行可能需要加载 4B 权重；当原 SFT 未检索就提交答案时，会释放它再加载定向 SFT A，延迟会增加。模型权重、索引和两个虚拟环境按 README 准备。

## 规则与数据

固定规则：原搜索 SFT 正常结束且搜索次数为 0 时，从原问题重新运行定向 SFT A；其他情况保留原 SFT。路由只读取原模型可见的终止状态和搜索次数，不读取标准答案或评分。它改善的是系统的端到端结果，不是单个权重的能力。

用已有的完整同题轨迹回放，成功标准是答案匹配且已看到全部支持证据：

| 队列 | 原 SFT | 始终用 A | 早答复核路由 | 触发复核 |
| --- | ---: | ---: | ---: | ---: |
| 本地 dev | 20/100 | 24/100 | **24/100** | 37/100 |
| 本地 test | 27/100 | 27/100 | **31/100** | 36/100 |
| 外部 HotpotQA | 21/100 | 24/100 | **22/100** | 31/100 |
| 外部 2WikiMultiHopQA | 26/100 | 37/100 | **35/100** | 40/100 |

本地 test 在本次规则形成前已被打开，以上是事后回放，不能当作新冻结的独立验证。两批外部数据同样来自此前已完成的评测轨迹，不能宣称新采样评测或统计显著优效。页面的自由提问没有参考答案，不能即时声称答对。复核时最多运行两次 4B 推理，响应时间会增长。

复算命令：

```powershell
.\.venv\Scripts\python.exe -m hotpot_search.routed_eval
```

逐队列的配对差值、bootstrap 区间和源文件 SHA-256 保存在 `runs/reopd/routed-eval/report.json`。该脚本拒绝缺失评分、重复键或两组题目不一致的轨迹。
